# Как вносить правки

## Порядок работы

Ветка `main` защищена, напрямую в неё не пушим. Каждая правка идёт через короткую ветку и pull request.

```sh
git switch main && git pull
git switch -c web/lesson-07          # ветка: <предмет>/<что делаем>
# ... правки ...
git add -A && git commit -m "web: lesson 7, формы"
git push -u origin web/lesson-07
```

Дальше открыть pull request на GitHub. После одобрения он вливается через squash merge, ветка удаляется.

Ветки живут недолго: одна ветка — один конспект или одна работа. Отдельных долгих веток под предметы не заводим, предметы разделены папками.

## Сообщения коммитов

Формат: `<предмет>: <что сделано>`.

```
rpm: конспект лекции 3, ветвление в git
mobile: lunch tray, навигация
testing: pytest_2, фикстуры
docs: поправил ссылки в README
```

## Конспекты

- Формат — Markdown, один файл на тему.
- Имя файла начинается с номера, чтобы темы шли по порядку: `01-жизненный-цикл-по.md`.
- Картинки кладём в `assets/` внутри папки дисциплины и перед коммитом сжимаем.
- Ссылки между конспектами — относительные.

## Практические работы

- Небольшая работа — папка внутри `practice/<предмет>/`, например `practice/web/lesson-07/`.
- Крупный проект (Unity, Android) — отдельный репозиторий в организации, а в `README.md` предмета добавляем на него ссылку.
- В корне работы желателен короткий `README.md`: что за задание и как запустить.

## Чего в репозитории быть не должно

Репозиторий публичный, а история git хранит всё навсегда.

- **Большие бинарные файлы**: презентации, сканы, видео, сборки (`.apk`, билды Unity). Их кладём на облачный диск или в Releases, в репозитории оставляем ссылку.
- **Результаты сборки и зависимости**: `build/`, `node_modules/`, `Library/`, `.venv/`. Они уже перечислены в `.gitignore`.
- **Именные отчёты и персональные данные**: отчёты с ФИО, номера зачёток, контакты.
- **Чужие материалы**: слайды преподавателей, сканы учебников, файлы курсов — только с разрешения автора.
- **Пароли, ключи, токены**.

Отчёт в `.docx` стоит переписать в Markdown: его можно читать на GitHub и видно, что изменилось.
